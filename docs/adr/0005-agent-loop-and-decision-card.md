# ADR-0005：Agent 循环、工具安全与决策卡

- 状态：已接受（2026-08）
- 关联模块：`src/harness/harness.ts`、`src/harness/decision-card.ts`

## 背景

工具调用循环（思考→工具→再思考）有死循环与失控风险；重大剧情转折不应由模型单方面决定，需要用户介入。

## 决策

- **循环上限**：`maxLoopTurns`（默认 10），到顶强制终止并外发最后一次正文，防模型死循环烧 token。
- **过程性内容剔除**：中间轮的"思考正文"不外泄，只有最终剧情流式给用户——工具中间输出不污染剧情。
- **错误回填**：工具执行失败以 `role=tool` 回填给模型自我修正，不中断剧情。
- **决策卡**：`decide` 工具请求用户拍板重大转折，harness 暂停循环推卡片（120s 无响应默认选第一个），选择注入后续生成，`decisions.jsonl` 留痕可审计。
- **掷骰**：`roll` 工具把检定结果交给用户真随机投掷，模型不得擅改点数——确定性命运节点。
- **token 护栏**：每会话每日上限（`maxTokensPerDay`），达到即拦截并提示。

## 后果

- 正面：循环必然终止、用户对重大转折保留否决权、成本有硬上限。
- 代价：决策卡依赖前端交互（CLI/Web 均已实现）；`decide`/`roll` 的拦截点位于 harness 内，无法被模型绕过（工具注册表在服务端）。
