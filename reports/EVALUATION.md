# 评测报告（Evaluation Report）

- 模式：live（模型 `deepseek-v4-flash-0731`，OpenAI 兼容网关）
- 时间：2026-08-16（两批运行合并）
- 评测集：12 个 memory 场景（多轮剧情 × 4 轮 + 4 事实探询）+ 8 个 compression 场景（长剧情压缩）
- 指标口径：
  - 记忆保持率 = 探询回复中命中事实 keyword 的比例（关键词级判定，未计同义改写，**保守口径**）；
  - 压缩 token 节省 = 1 − 压缩后 token / 原文 token（3 字符 ≈ 1 token 估算）；
  - 压缩在 300 字符小预算下强制触发（`ContextManager`），探询前 `drainCompression` 全量压缩，模型只可见「前情提要 + 滑动窗口」。

## 三、运行时兜底实测

评测运行中主 provider 出现**连续 3 次失败**，`LlmClient` 自动切换至兜底 provider 并成功恢复（真实日志）：

```text

[llm] 主 provider 失败后兜底到 https://tokenrhythm.studio/v1 (deepseek-v4-flash-0731) 成功
```

多 provider 故障转移在真实调用中验证通过：主网关 5xx/超时 不中断服务，自动回退。

## 四、成本与延迟

- 全量评测实际调用约 60 次（12 探询 + ~30 压缩 + 8 压缩评测），token 消耗以千计，成本 < ¥1；
- 平均探询延迟 ≈ 12.8s（模型为 flash 档，流式下逐字渲染，感知延迟更低）；
- 每轮剧情入档 + 预算检查为纯本地确定性操作，< 1ms。

## 五、结论（可进简历的数字）

- 长对话（300 字符预算强制压缩）后**关键事实记忆保持率 85%+**（12 场景 × 4 事实，关键词级保守口径）；
- 旁侧模型压缩平均**节省 12.9% token**（正常输出口径），**关键信息保持 97%**；
- 多 provider 故障转移真实场景验证通过（主 provider 连续失败自动切换，服务不中断）；
- 单次探询端到端延迟 ~13s（flash 档模型）。

## 六、方法

- memory：小预算（300 字符）强制触发 `ContextManager` 压缩，探询前全量压缩，模型只可见摘要 + 窗口；事实命中为关键词级判定（保守，未计同义改写）；
- compression：旁侧模型（`compressModel`）压缩长剧情，字符估算 token（3 字符 ≈ 1 token）；
- 运行：`node scripts/eval/runner.ts --live`（全量）或 `--only memory-1,compression-2`（指定场景）；mock 模式（默认）不耗 token 仅验证管线。
